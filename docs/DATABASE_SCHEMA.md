# Database schema (initial migration)

The numbered migrations are applied with the explicit `cis-fin migrate --apply` command after reviewing `cis-fin migrate --dry-run`. Applying them requires PostgreSQL schema-creation privileges. Always verify the migration ledger on the target environment; the app and ingestion CLI stop before writes if the ledger is inconsistent or migrations remain pending.

All entity UUIDs are generated by the application, not by a database-specific extension. Foreign keys use `ON DELETE RESTRICT` so approved research data is not silently removed by deleting a parent record.

| Table | Purpose and important constraints |
|---|---|
| `companies` | Company metadata with unique symbol, separate sector and industry, optional constituent-list provenance, and `profile_status` (`pending_review` or `verified`). PDF-detected profiles are stored as pending review rather than represented as verified constituent data. |
| `researchers` | Identifiable accounts with `owner`, `researcher`, or `reviewer` role labels. This table is not itself authentication or authorization enforcement. |
| `company_assignments` | Assignment history and workflow state. A partial unique index prevents multiple active owners for one company. Five users are the initial rollout target, not a schema limit. |
| `documents` | Source metadata, public/confidential classification, object key, SHA-256 checksum, extraction/job statuses, original page count, selected inclusive page range, and extracted page count. `(company_id, checksum)` prevents duplicate copies for the same company. |
| `chunks` | Extracted text with page range and chunk index. Chunk UUID is stable per document/checksum/index/content; chunk index is unique per document. Identical text appearing on different pages is allowed as a distinct occurrence. |
| `questions` | Candidate question and generation/taxonomy provenance, separate validation and review states. Approval requires `validation_status = 'valid'`. |
| `chunk_question_evidence` | Many-to-many chunk/question evidence with exact quote and independent semantic-support status. |
| `question_generation_checkpoints` | Per-chunk model/prompt status (`generated` or `abstained`) so bounded batches can resume without repeating completed chunks. |
| `embedding_registry` | Stable vector identifier, collection/model/version/dimensions and indexing state. Same chunk/model/version/collection is unique. |
| `processing_jobs` | Stage checkpoints, retry count/cap, lease, recoverable status, and sanitized error fields. Completion timestamp is required exactly when status is completed. |
| `audit_events` | Actor, action, entity, timestamp and structured details for reprocessing and review audit history. Do not place credentials or source secrets in details. |

The migrations do not insert or invent Nifty 50 constituents. `cis-fin add-company` remains available for owner-verified, dated constituent/classification information. Streamlit instead extracts profile suggestions from the uploaded report and, after user review, can create a `pending_review` profile; it never labels a PDF inference as an official constituent source.

## What this does not provide yet

- Authentication, database role grants, or enforcement that only designated reviewers can approve.
- Repository/service code for safe upserts and job transitions.
- Semantic question validation, question approval UI, and reviewer authorization. Local candidate generation checks quote presence but leaves semantic support pending human review.
- Object storage/Qdrant consistency or a distributed transaction.
- Production deletion policies beyond restrictive foreign keys.

The migration ledger tracks a numbered file and its SHA-256 checksum. Never edit a migration already applied; add a new numbered migration instead. The runner takes a PostgreSQL advisory transaction lock and applies pending SQL and ledger records in the same transaction.
